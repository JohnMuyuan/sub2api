# Claude 请求一致性诊断与重试保护

适用于 Anthropic OAuth 和 Setup Token 账号，随服务启动自动启用，无需新增配置。

## 一致性诊断

在最终请求构建完成后检查 CLI UA 与 billing 版本、会话头与 metadata 会话 ID、流式标志与 helper 头、重复单值头和混用认证方式。只检查可识别的已有字段，不猜测缺失字段。

在容器日志中搜索 `claude.request_consistency`，查看内部账号 ID 与固定的 `issue` 代码。同一客户端请求中的同类问题只记录一次。诊断不修改请求，不添加任何上游诊断字段。原有 ClaudeMimicDebug 摘要也不再包含原始会话标识、账号名称、请求 URL 或系统提示词。

## 重试保护

- 一次客户端请求对 Claude 订阅账号最多发送 5 次，Messages、Chat/Responses 兼容路径、400 修复请求与账号切换共享预算；只有首次发送后 10 秒内可启动补发，不会用这个期限中断正常长响应。
- 401/403 不再在同一账号重复提交；可以按既有调度逻辑切换其他账号。
- 429/503/529 遵守 `Retry-After` 秒数或 HTTP 日期。缺失或非法时至少等待 1 秒；超出本次重试窗口则跳过该账号，不压缩等待时间。
- 已接收成功响应、已继续向客户端写出内容，或网络错误无法确认请求未送达时，停止本次请求的后续补发，减少重复生成。只有能确认连接阶段失败且尚未取得连接时才保留原有网络故障切换流程。
- 同一次请求对同一账号复用首次选定的 TLS profile；已有 `X-Stainless-Retry-Count` 按该账号实际发送次数更新，首次为 0。不会新增不存在的该头。
- 本地保护拒绝不计为账号健康故障。日志事件为 `claude.retry_protection`，`reason` 是固定原因代码。

这些保护优先避免重复提交，网络结果不明或响应体损坏时可能需要客户端人工重新发起请求。API Key 和其他平台仍使用原有重试策略。这里的请求预算不会限制用户主动发起的多次独立请求。
