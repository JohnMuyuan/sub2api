# 本地 ZIP 数据库备份

系统设置 → 数据备份 → **本地 ZIP 备份**，保存绝对目录后，在“备份操作”的存储位置选择本地 ZIP，然后创建备份。定时备份配置也有相同的存储位置选项，复用现有 cron、保留天数、保留份数和月度归档规则。

备份不依赖 S3。ZIP 内的 `database.sql` 为既有 PostgreSQL 全库导出，包含数据库中的账号、配置、用量等数据。备份记录支持下载、删除和通过原有管理员密码确认流程恢复。SQL 内可能包含账号凭据等敏感数据，应妥善保管。

新版在启动时将字段加密密钥持久保存到数据库的 `security_secrets` 表（登录 JWT 密钥原本就保存在这里）。后续生成的 ZIP 同时包含 `database.sql` 和带 SQL SHA-256 的 `manifest.json`，因此密钥能随数据库迁移。启动时数据库保存的密钥优先于新服务器环境变量中的不同密钥，保证恢复的数据可解密；密钥轮换需要配合数据库内加密字段迁移，不能仅修改环境变量。

## 新服务器上传恢复

1. 将现有部署升级到支持上传恢复的版本并重启，重新生成一份新版 ZIP，下载到自己电脑保存。
2. 新服务器部署相同或更新的自定义版本，使用兼容的 PostgreSQL（当前镜像配套 PostgreSQL 18 客户端）、新的 Redis，并完成初始化登录。
3. 系统设置 → 数据备份 → **上传 ZIP 恢复**，选择文件并点击“上传、校验并恢复”。无需先配置本地目录或 S3。
4. 校验通过后确认覆盖数据库，输入**新服务器当前管理员密码**。已有 2FA 策略仍按原流程验证。
5. 恢复完成后点击“重启服务并返回登录页”，用**备份中的原管理员账号**登录。Docker 需有 `always` 或 `unless-stopped` 重启策略。

上传只登记并校验备份，不会立即改写数据库。导入文件以随机名称存入持久数据目录的 `backup-imports`，不信任上传文件名，默认七天过期。ZIP 上限 256 MiB，解压 SQL 上限 8 GiB；反向代理和全局请求体限制可能更小，上传前应在 1Panel 网站设置中配置相应大小和超时。验证和恢复会在临时目录完整展开 SQL（权限 0600），需预留足够磁盘空间。

ZIP 只允许普通 `database.sql` 以及可选的 `manifest.json`，拒绝重复条目、链接、目录穿越、不支持的文件和版本。校验 ZIP CRC 和新版 SQL 摘要后才调用数据库恢复；`psql` 使用单事务及 `ON_ERROR_STOP=1`，SQL 错误会中断事务。仅上传自己信任的备份：数据库 SQL 本身是由数据库用户执行的程序。

旧版只有 `database.sql` 的 ZIP 仍可上传，但不会自动补出当时没备份的密钥，页面会额外提示确认。旧备份迁移到新服务器时仍需原加密密钥；升级后重新生成新版 ZIP 才能实现自动携带密钥。

环境变量、外部图片对象、独立 Worker 的密封恢复档案及其 `key.bin`、服务器配置文件不属于此数据库备份，请单独保存。正在进行的 MFA 换绑或独立 Worker 恢复流程应先完成再迁移。服务器数据库地址、端口、Docker 网络和挂载沿用新服务器配置，不会被旧服务器配置覆盖。备份内含敏感数据和密钥，不要公开分享，并保留一份服务器外的副本。

## Docker / 1Panel

填写的是**容器内部路径**。如果现有部署已持久挂载 `/app/data`，可以选 `/app/data/backups`，无需额外挂载。

需要存到宿主机指定位置时，在原应用容器增加挂载，例如：

```yaml
volumes:
  # 保留原有挂载，再增加这一项
  - /opt/sub2api-backups:/app/backups
```

然后在页面填写 `/app/backups`。宿主机 `/opt/sub2api-backups` 需要给予容器运行用户写权限；当前自定义镜像使用 UID/GID `1000:1000`。请仅调整新建备份目录的权限。

目录不应放在网站公开目录中。ZIP 文件以仅运行用户可读写的权限创建；新目录默认仅运行用户可访问。备份生成成功前使用临时文件，失败时清理临时文件。大文件在浏览器下载时会占用浏览器内存，也可以直接从服务器备份目录取走 ZIP。

修改保存目录只影响以后创建的备份，旧记录继续使用原目录。多实例部署应使用各实例可访问的共享挂载；本地备份保留在生成它的磁盘上。定时保留策略针对备份记录统一执行，包括 S3 和本地 ZIP。

## 校验

```sh
cd backend
go test -tags unit ./internal/service -run 'Test(LocalZIP|Backup|Restore)' -count=1
go test ./internal/handler/admin ./internal/server/routes -run TestBackup -count=1
golangci-lint run --timeout=10m
```

```sh
cd frontend
pnpm exec vitest run src/views/admin/__tests__/BackupView.spec.ts
pnpm run build
```

本地路径访问由 `os.Root` 约束文件边界；记录中的文件名和 ID 也会校验。下载与目录修改接入原有管理员 step-up 验证；恢复继续要求管理员密码。
